# Relay / 驿站 · 需求文档

**版本**：v1.3-draft
**日期**：2026-09-18
**状态**：designing

## 1. 项目目标

Relay（驿站）是一款仅面向 Apple Silicon 的 macOS 菜单栏应用，用于集中查看多个 AI 服务商、多个账户的余额、消费和用量。用户无需逐个登录站点，即可在菜单栏和展开面板中看到可比较的账户快照与短期趋势。

### 目标用户

- 同时使用多个 AI API 供应商或中转站的个人开发者。
- 需要管理同一供应商多个账户的用户。
- 希望凭据和统计数据保留在 Apple 生态内的用户。

### 核心原则

- 只读监控，不充值、不扣费、不代理模型调用。
- 本地优先；单账户失败不能影响其他账户。
- 不伪造缺失指标：未知、未支持和真实的 0 必须区分。
- 凭据只进入 Keychain，不写入普通文件、数据库、日志或 CloudKit 明文字段。

## 2. 目标平台与形态

- 平台：macOS 27，Apple Silicon。
- 形态：菜单栏常驻，默认不显示 Dock 图标；可从设置打开独立窗口。
- UI：遵循 macOS 27 Liquid Glass；视觉细节由 UI 阶段确定。
- 网络：应用直接访问供应商 API，不经过 Relay 自建服务器。
- 同步：目标能力为 CloudKit 私有库同步元数据/历史数据；凭据同步是否启用仍需确认。

## 3. 首期范围

### P0：可用闭环

1. Pipio 单/多账户添加、编辑、启用、禁用和删除。
2. Keychain 安全保存系统令牌和用户 ID 关联信息。
3. 读取站点状态、账户余额/累计数据、今日统计（接口支持时）。
4. 菜单栏摘要、首页账户列表、账户详情。
5. 手动刷新、定时刷新、失败保留旧数据、退避重试。
6. 本地历史数据和设置持久化。

### P1：产品完整度

1. DeepSeek 余额接入；网页 userToken 用量能力单独评估。
2. 7 日/30 日趋势、分模型用量。
3. 开机启动、快捷键、低余额阈值和通知。
4. CloudKit 私有库同步账户元数据、偏好和聚合历史。

### P2：可选扩展

- 自定义 New API 兼容站点。
- 配置导入/导出。
- 更多供应商适配器。

## 4. Pipio 接口验证结论

验证时间：2026-09-18。验证只使用只读请求。

### 4.1 基址必须拆分

用户提供的 `https://pipio.io/v1` 是 OpenAI 兼容模型 API 基址，不是管理 API 基址。

- 模型 API：`https://pipio.io/v1/...`
- 管理 API：`https://pipio.io/api/...`
- 站点原点：`https://pipio.io`

不能把管理路径拼成 `/v1/api/...`；该路径会返回 404。

### 4.2 已确认接口行为

| 接口 | 结果 | 结论 |
|---|---|---|
| `GET /api/status` | 200，无需认证 | 可获取站点版本、`quota_per_unit`、币种和功能开关 |
| `GET /api/user/self` | 未带 `Pipio-User` 时 401 | 需要数值用户 ID |
| `GET /api/log/self/stat` | 未带 `Pipio-User` 时 401 | 需要数值用户 ID |
| `GET /api/log/self` | 未带 `Pipio-User` 时 401 | 需要数值用户 ID |
| `GET /v1/models` | 当前提供的令牌返回 401 `Invalid token` | 该令牌不能当作模型 API Key 使用，或令牌已失效/类型不匹配 |

`/api/status` 当前返回 `quota_per_unit = 500000`，但应用每次新增站点或定期刷新时应动态读取，不硬编码为永久值。

### 4.3 当前阻塞

账户管理接口要求：

```http
Authorization: Bearer <system-token>
Pipio-User: <numeric-user-id>
```

当前没有提供数值用户 ID，且不能从这段随机令牌安全、可靠地反推出用户 ID，因此尚不能验证账户余额与日志返回结构。用户 ID 应由用户从 Pipio 账户/控制台提供，或在已登录网页中从账户信息响应获取；Relay 不应枚举用户 ID。

> 安全提示：本次提供的令牌已经出现在会话中，应视为已暴露；验证结束后建议在 Pipio 后台轮换。项目文档不得记录该令牌。

## 5. 核心功能

### 5.1 账户管理

- 支持 Pipio、DeepSeek；“自定义站点”延后至 P2。
- 同一供应商可添加多个账户。
- Pipio 必填：站点 URL、系统令牌、数值用户 ID、账户显示名。
- 添加时依次验证站点状态、账户自查接口和统计接口。
- 用户可以禁用账户；禁用不删除已有历史数据。
- 删除账户时删除本地数据和 Keychain 项；CloudKit 已同步数据通过 tombstone 删除。

### 5.2 菜单栏

- 默认显示图标 + 今日已知消费。
- 可切换：仅图标、今日消费、总余额。
- 若部分账户今日数据未知，摘要必须标记为“不完整”，不得把已知和当作全量总和而不提示。
- 状态应同时使用图形/文本语义，不能只依赖颜色。

### 5.3 首页

- 总余额、今日已知消费、正常/异常账户数、最近成功刷新时间。
- 账户卡片：供应商、显示名、余额、今日消费、状态、数据新鲜度。
- 7 日趋势仅汇总具有可比较币种和有效数据的账户。
- 支持手动刷新、添加账户、进入设置和账户详情。

### 5.4 账户详情

- 余额、今日消费、本月消费。
- 调用次数、Token、按模型统计、缓存命中率（仅接口明确支持时）。
- 7 日/30 日消费趋势。
- 未支持字段隐藏或显示“暂不支持”；未知值不显示为 0。

### 5.5 刷新与容错

- 默认间隔 5 分钟，可选 1/5/15/30 分钟。
- 每账户独立刷新，可限制并发数量。
- 网络/5xx 可退避重试；401/403 不自动高频重试，提示更新凭据。
- 失败保留最近一次成功快照并标记过期。
- 应保存最近成功时间和最近错误摘要，不保存敏感请求头或响应。

### 5.6 iCloud 同步

- CloudKit 私有库：账户元数据（不含明文凭据）、聚合历史、用户主动修改的偏好、删除 tombstone。
- Keychain：系统令牌、API Key、userToken。
- 未登录 iCloud 或网络不可用时，本机功能必须可用。
- 关闭同步时默认仅停止同步；是否删除云端副本必须二次确认。

## 6. 数据能力降级

| 档位 | 条件 | 展示策略 |
|---|---|---|
| 完整 | 余额、今日、分模型、缓存均可用 | 展示全部 |
| 标准 | 余额、今日、分模型可用 | 隐藏缓存命中率 |
| 基础 | 余额、累计数据可用 | 今日区域显示暂不支持/未知 |
| 仅余额 | 只有余额 | 只展示余额与更新时间 |
| 异常 | 网络、认证或解析失败 | 保留旧数据并显示错误/过期状态 |

能力由每个 `ProviderAdapter` 在运行时声明，不用供应商名称写死 UI。

## 7. 非功能要求

### 安全

- Keychain 条目按账户隔离。
- 所有日志默认脱敏；禁止输出令牌、Cookie、Authorization、完整响应体中的个人信息。
- 只允许 HTTPS；自定义站点若支持，默认拒绝无效证书和 HTTP。

### 性能

- 菜单栏打开应立即展示本地缓存，不等待网络。
- 网络刷新在后台执行，不阻塞 UI。
- 历史数据按日聚合，避免长期保存全部原始日志。

### 可靠性

- 数据解析采用容错 DTO；供应商新增字段不应导致整体失败。
- 金额使用 Decimal，时间统一保存为 UTC，按用户时区计算“今日”。
- 跨币种默认不直接求和；必须先有明确汇率来源和更新时间。

## 8. 验收标准

### AC-001 Pipio 添加账户

给定有效站点、系统令牌和数值用户 ID；当用户验证并保存；则应用应确认 `/api/status` 与 `/api/user/self` 可用，将凭据写入 Keychain，并创建首个本地快照。

### AC-002 缺少用户 ID

给定系统令牌但未填写数值用户 ID；当用户验证；则应用不得请求账户数据，并明确提示 `Pipio-User` 为必填。

### AC-003 单账户失败

给定多个账户；当其中一个账户超时或认证失败；则其他账户仍能完成刷新，失败账户保留旧数据并显示过期/错误状态。

### AC-004 未支持指标

给定供应商未返回缓存命中率；当打开详情；则该字段隐藏或显示暂不支持，不显示 `0%`。

### AC-005 凭据保护

当添加、刷新、同步、导出或记录错误时；系统令牌不得出现在普通文件、CloudKit 记录、控制台日志和 UI 回显中。

## 9. 非目标

- 自动充值、扣费或调用模型。
- Relay 自建账号、服务器或跨 Apple ID 数据共享。
- 浏览器爬虫和绕过站点认证。
- iPhone、iPad、Android、Web 客户端。
- 深度财务分析和税务/账单核对。

## 10. NEEDS_CONFIRMATION

1. Pipio 数值用户 ID（用于继续验证 `/api/user/self` 和日志接口）。
2. 当前令牌的真实类型：管理“系统令牌”、模型 API Key，还是已失效令牌。
3. iCloud 是否为首个可发布版本的必需项，还是 P1。
4. Keychain 凭据是否允许设置为 iCloud 可同步；默认建议不启用，按设备录入。
5. DeepSeek 网页 userToken 是否接受非官方接口稳定性风险；建议首期只做官方余额。
6. 今日消费不完整时，菜单栏是否显示“已知合计 + 不完整标记”（建议是）。
7. 历史保留期：建议本地 90 天日聚合、CloudKit 30 天日聚合。
8. 低余额阈值：建议按账户配置，默认 10 USD 或等值金额。
9. 是否存在多币种账户；若有，需要确认汇率来源。
