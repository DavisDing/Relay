# Relay / 驿站 · 需求文档

**版本**：v1.5-draft
**日期**：2026-09-18
**状态**：designing

## 1. 项目目标

Relay（驿站）是一款仅面向 Apple Silicon 的 macOS 菜单栏应用，用于集中查看多个 AI 服务商、多个账户的余额、消费和用量。用户无需逐个登录站点，即可在菜单栏和展开面板中看到可比较的账户快照与短期趋势。

### 目标用户

- 同时使用多个 AI API 供应商或中转站的个人开发者。
- 需要管理同一供应商多个账户的用户。
- 希望凭据和统计数据保留在 Apple 生态内的用户。

### 核心原则

- 只读监控，不充值、不扣费、不代理模型调用。
- 本地优先；单账户失败不能影响其他账户。
- 不伪造缺失指标：未知、未支持和真实的 0 必须区分。
- 系统令牌和 Pipio 用户标识的真实值仅在请求期间短暂驻留内存，持久化时只进入 Keychain；不得写入项目源码、文档、普通文件、SwiftData、同步文件、日志或 CloudKit，文档只能使用抽象字段名或占位符。

## 2. 目标平台与形态

- 平台：macOS 27，Apple Silicon。
- 形态：菜单栏常驻，默认不显示 Dock 图标；可从设置打开独立窗口。
- UI：遵循 macOS 27 Liquid Glass；视觉细节由 UI 阶段确定。
- 网络：应用直接访问供应商 API，不经过 Relay 自建服务器。
- 同步：首期使用用户选择的文件夹同步非秘密数据；文件夹可以位于 iCloud 云盘。由于当前无付费开发者账户和稳定签名，首期不依赖 CloudKit Container，也不承诺凭据跨设备同步。

## 3. 首期范围

### P0：可用闭环

1. Pipio 单/多账户添加、编辑、启用、禁用和删除。
2. Keychain 安全保存运行时认证信息（系统令牌和数值用户 ID）；项目与文档不记录真实值。
3. 读取站点状态、账户余额/累计数据、今日统计（接口支持时）。
4. 菜单栏摘要、首页账户列表、账户详情。
5. 手动刷新、定时刷新、失败保留旧数据、退避重试。
6. 本地历史数据和设置持久化。
7. 首期通过用户选择的同步文件夹保存账户元数据、偏好和聚合历史；目录可选择在 iCloud 云盘，令牌和用户 ID 不进入同步文件。

### P1：产品完整度

1. DeepSeek 官方余额接口接入；不使用浏览器会话 userToken 或私有网页接口。
2. 7 日/30 日趋势、分模型用量。
3. 开机启动、快捷键、低余额阈值和通知。

### P2：可选扩展

- 自定义 New API 兼容站点。
- 配置导入/导出。
- 更多供应商适配器。

## 4. Pipio 接口验证结论

验证时间：2026-09-18。验证只使用只读请求。

### 4.1 基址必须拆分

用户提供的 `https://pipio.io/v1` 是 OpenAI 兼容模型 API 基址，不是管理 API 基址。

- 模型 API：`https://pipio.io/v1/...`
- 管理 API：`https://pipio.io/api/...`
- 站点原点：`https://pipio.io`

不能把管理路径拼成 `/v1/api/...`；该路径会返回 404。

### 4.2 已确认接口行为

| 接口 | 结果 | 结论 |
|---|---|---|
| `GET /api/status` | 200，无需认证 | 可获取站点版本、`quota_per_unit`、币种和功能开关 |
| `GET /api/user/self` | 使用管理令牌 + 用户 ID 返回 200 | 可获取当前账户的数值配额、已用配额、请求数、状态和权限元数据 |
| `GET /api/log/self/stat` | 使用管理令牌 + 用户 ID 返回 200 | 返回 `data.quota`、`data.rpm`、`data.tpm`；用于区间统计能力探测 |
| `GET /api/log/self` | 使用管理令牌 + 用户 ID 返回 200 | 返回分页日志；可读取模型、配额、输入/输出 Token、时间和流式标记 |
| `GET /v1/models` | 当前管理令牌返回 401 `Invalid token` | 管理令牌不能当作模型 API Key 使用；两种令牌必须分开建模 |

本次验证确认：用户 ID 可从已登录 Pipio 网页对 `/api/user/self` 的 Network 请求中读取，且请求头使用 `Pipio-User`；本次验证得到的 ID 不写入仓库。Relay 首期仍要求用户在账户表单中输入或粘贴该数值 ID，不读取 Safari Cookie，也不枚举 ID。

`/api/status` 返回 `quota_per_unit`、币种和展示类型，但该值必须在运行时读取，不硬编码。`/api/log/self` 支持 `start_timestamp`、`end_timestamp`、`page`、`page_size` 参数；日志 `created_at` 为 10 位 Unix 秒级时间戳。统计接口字段为供应商原始计量值，金额换算必须由适配器结合 `quota_per_unit` 完成，并保留原始单位。

### 4.3 管理接口请求约束

账户管理接口要求：

```http
Authorization: Bearer <management-token>
Pipio-User: <numeric-user-id>
```

其中 `Pipio-User` 是当前账户的数值身份，不是系统令牌的可逆编码，也不能可靠地从令牌反推。已登录网页抓包/Network 面板可以用于用户本人找回该值，但 Relay 不应接管浏览器会话或保存 Cookie。

> 安全提示：本次提供的令牌已经出现在会话中，应视为已暴露；验证结束后建议在 Pipio 后台轮换。项目文档不得记录该令牌。

## 5. 核心功能

### 5.1 账户管理

- 支持 Pipio、DeepSeek；“自定义站点”延后至 P2。
- 同一供应商可添加多个账户。
- Pipio 必填：站点 URL、系统令牌、数值用户 ID、账户显示名；令牌和用户 ID 仅运行时输入并写入 Keychain，不进入账户元数据。
- 添加时依次验证站点状态、账户自查接口和统计接口。
- 用户可以禁用账户；禁用不删除已有历史数据。
- 删除账户时删除本地数据和 Keychain 项；同步文件通过 tombstone 传播删除。

### 5.2 菜单栏

- 默认显示图标 + 今日消费；仅当参与汇总的账户今日数据完整时显示金额。
- 可切换：仅图标、今日消费、总余额。
- 今日数据不完整时隐藏今日消费字段，不显示部分合计，也不将未知值当作 0。
- 状态应同时使用图形/文本语义，不能只依赖颜色。

### 5.3 首页

- 总余额、今日消费（仅完整时）、正常/异常账户数、最近成功刷新时间。
- 账户卡片：供应商、显示名、余额、今日消费（仅该账户数据完整时）、状态、数据新鲜度。
- 7 日趋势仅汇总具有可比较币种和有效数据的账户。
- 支持手动刷新、添加账户、进入设置和账户详情。

### 5.4 账户详情

- 余额、今日消费、本月消费；今日数据不完整时不显示今日消费字段。
- 调用次数、Token、按模型统计、缓存命中率（仅接口明确支持时）。
- 7 日/30 日消费趋势。
- 未支持字段隐藏或显示“暂不支持”；未知值不显示为 0。

### 5.5 刷新与容错

- 默认间隔 5 分钟，可选 1/5/15/30 分钟。
- 每账户独立刷新，可限制并发数量。
- 网络/5xx 可退避重试；401/403 不自动高频重试，提示更新凭据。
- 失败保留最近一次成功快照并标记过期。
- 应保存最近成功时间和最近错误摘要，不保存敏感请求头或响应。

### 5.6 文件夹同步

- 首期不使用 CloudKit Container；用户在设置中选择一个同步目录，该目录可以位于 iCloud 云盘。
- 同步文件只包含账户元数据、聚合历史、用户偏好和删除 tombstone，不包含令牌、Pipio 用户 ID、API Key、userToken、Cookie 或原始日志。
- 凭据首期只保存在当前 Mac 的本地 Keychain。待未来具备稳定签名和相应能力后，再单独验证 iCloud Keychain 同步。
- 同步目录未选择、不可访问、冲突或离线时，本机功能必须继续可用。
- 关闭同步只停止读写同步文件，不删除本地数据；删除同步文件需二次确认。

### 5.7 汇率、历史和低余额

- Pipio 发布的站点换算参数作为该供应商的汇率/换算来源；保存来源和最后更新时间。
- 汇率刷新频率可配置，默认每 7 天一次；提供每天、每周、每月和仅手动选项。用户手动刷新账户时可选择同时强制刷新汇率。
- 汇率过期或获取失败时保留上次成功值并标记过期；没有可靠汇率时不跨币种汇总。
- 历史保留策略由用户选择：默认保留 1 年，或永久保留。仅保存日/模型聚合，不长期保存原始日志。
- 低余额阈值按账户配置，新增账户默认填充为 `20` 个账户展示币种单位；用户可修改或关闭提醒。

## 6. 数据能力降级

| 档位 | 条件 | 展示策略 |
|---|---|---|
| 完整 | 余额、今日、分模型、缓存均可用 | 展示全部 |
| 标准 | 余额、今日、分模型可用 | 隐藏缓存命中率 |
| 基础 | 余额、累计数据可用 | 隐藏今日消费字段 |
| 仅余额 | 只有余额 | 只展示余额与更新时间 |
| 异常 | 网络、认证或解析失败 | 保留旧数据并显示错误/过期状态 |

能力由每个 `ProviderAdapter` 在运行时声明，不用供应商名称写死 UI。

## 7. 非功能要求

### 安全

- Keychain 条目按账户隔离。
- 所有日志默认脱敏；禁止输出令牌、用户 ID、`Pipio-User`、Cookie、Authorization 和完整响应体中的个人信息。
- 只允许 HTTPS；自定义站点若支持，默认拒绝无效证书和 HTTP。

### 性能

- 菜单栏打开应立即展示本地缓存，不等待网络。
- 网络刷新在后台执行，不阻塞 UI。
- 历史数据按日聚合，避免长期保存全部原始日志。

### 可靠性

- 数据解析采用容错 DTO；供应商新增字段不应导致整体失败。
- 金额使用 Decimal，时间统一保存为 UTC，按用户时区计算“今日”。
- 跨币种默认不直接求和；仅使用供应商发布且未过期的汇率/换算参数，并保存来源和更新时间。

## 8. 验收标准

### AC-001 Pipio 添加账户

给定有效站点、系统令牌和数值用户 ID；当用户验证并保存；则应用应确认 `/api/status` 与 `/api/user/self` 可用，将凭据写入 Keychain，并创建首个本地快照。

### AC-002 缺少用户 ID

给定系统令牌但未填写数值用户 ID；当用户验证；则应用不得请求账户数据，并明确提示 `Pipio-User` 为必填。

### AC-003 单账户失败

给定多个账户；当其中一个账户超时或认证失败；则其他账户仍能完成刷新，失败账户保留旧数据并显示过期/错误状态。

### AC-004 未支持指标

给定供应商未返回缓存命中率；当打开详情；则该字段隐藏或显示暂不支持，不显示 `0%`。

### AC-005 凭据保护

当添加、刷新、同步、导出或记录错误时；系统令牌和 Pipio 用户 ID 的真实值均不得出现在项目文件、文档、SwiftData、同步文件、CloudKit 记录、控制台日志、诊断导出和 UI 回显中。

### AC-006 今日数据不完整

当今日消费数据缺失或仅覆盖部分账户时，菜单栏、首页汇总和对应账户卡片不得显示今日消费字段。

### AC-007 文件夹同步

当用户选择 iCloud 云盘或其他文件夹作为同步目录时，同步文件不得包含令牌、Pipio 用户 ID 或其他凭据；目录不可用时本地刷新和查看仍正常工作。

## 9. 非目标

- 自动充值、扣费或调用模型。
- Relay 自建账号、服务器或跨 Apple ID 数据共享。
- 浏览器爬虫、复制浏览器会话、私有网页接口和绕过站点认证。
- iPhone、iPad、Android、Web 客户端。
- 深度财务分析和税务/账单核对。
